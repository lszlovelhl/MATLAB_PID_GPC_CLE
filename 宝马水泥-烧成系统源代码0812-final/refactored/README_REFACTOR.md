## 2. 核心算法现状（原版问题）

**GPC（`gpc_clac.m`）**
- 预测时域 `N=80`、控制时域 `Nu=20`、输出系数 `0.7` 全部硬编码在函数体，换窑线必须改代码。
- 每个控制周期（约 3s）都重新求解 80 阶 Diophantine 递推并组装矩阵，是主要在线开销（约 2.7ms/次）。
- `olddeltaU=u(2)-u(1)` 只取单步差分，且整套实现仅对「一阶纯比例模型（na=1, nb=0）」成立。
- 在线递推辨识段（THETA/P）经确认是**死代码**：结果从未反馈回 A、B，也不影响输出 u，纯属每周期无效计算。
- 中文注释 GBK 乱码、冗余空行多。

**PID（`pid_calc.m`）**
- `du = kp*((e0-e1) + 1/ti*e0 + td*(e0-2*e1+e2))` 中 `ti=0` 时除零 → 输出冲成 Inf/NaN。
- 参数索引（行 7/8/9/10/11/12/13）无命名、无注释、无输入校验。

---

## 3. 重构改进点

### GPC（`gpc_clac_v2` + `gpc_matrices_v2`）
1. **参数化**：`N`、`Nu`、`control_gain`、`deltaU_history`、缓存开关全部通过 `opts` 结构体配置，默认值 = 原版数值，**默认行为逐位一致**。
2. **性能**：预测矩阵只依赖 A/B/N/Nu，模型不变时可缓存复用（`use_cached=true`），避免每个周期重算 Diophantine。
3. **可扩展**：`deltaU_history` 可设为 `nb+1`，从单步近似升级为标准 GPC 的多步预测（默认仍为单步，保证现场行为不变）。
4. **消除死代码**：在线递推辨识默认关闭（不影响输出），保留 `use_rls_online` 开关供需要时启用。
5. 补输入校验（时域为正整数、柔化因子兜底、Nu≤N），命名清晰、注释修正。

### PID（`pid_calc_v2`）
1. **修复除零**：`ti<=0` 时积分项置 0 并告警，避免输出冲成 Inf/NaN（正常参数下与原版逐位一致）。
2. **健壮性**：13 元素输入长度校验、命名 + 每行语义注释、统一列向量。
3. 控制律、死区、限幅、误差滚动逻辑保持与原版完全一致。

## 5. 如何接入现场（替换方式）

在 `on_timer.m` 等调用处，用重构版替换原版：

```matlab
% 原版
u = gpc_clac(A, B, P, yout1, Up1, sp, gpc_a, gpc_lmd);
% 重构版（默认行为与原版一致）
u = gpc_clac_v2(A, B, P, yout1, Up1, sp, gpc_a, gpc_lmd);
% 若模型参数固定，可进一步缓存矩阵提速：
u = gpc_clac_v2(A, B, P, yout1, Up1, sp, gpc_a, gpc_lmd, ...
                struct('use_cached', true));
```

```matlab
% 原版
pidloop(:,8) = pid_calc(pidloop(:,8)');
% 重构版（正常参数行为一致，ti=0 不再崩）
pidloop(:,8) = pid_calc_v2(pidloop(:,8)');
```

## 6. 建议的后续优化（本次未做，供参考）

- **启用真正的在线辨识**：将辨识结果反馈回 A、B，实现模型在线自校正（`use_rls_online=true` + 恢复反馈代码）。需先在离线数据上验证辨识收敛性，避免破坏现场稳定性。
- **多步 Δu 预测**：对 nb>0 的模型，将 `deltaU_history` 设为 `nb+1`，提升预测精度。
- **PID 抗饱和**：如需严格抗积分饱和，可将积分项改为误差累加 + clamping（注意这属于行为变更，需现场复核）。
- **统一 10 个工程**：本次仅做代表工程，可基于重构后的核心函数库统一其余 9 个水泥厂工程，消除重复。
